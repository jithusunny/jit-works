# Architecture decision records

Use an ADR only for an accepted technical choice that is important, cross-cutting, or expensive to reverse. Ordinary implementation choices belong in code, tests, and the work issue.

1. Discuss the unresolved choice in a GitHub Decision issue.
2. Once accepted, copy `0000-template.md` to the next numbered file.
3. Record the context, decision, consequences, and evidence briefly.
4. Commit the ADR with the implementation or immediately before it, then close the Decision issue.

ADRs are append-only history. Supersede an old ADR with a new one instead of silently rewriting the old decision.
